# Tagged-PDF qualification tools

These tools measure the real PlateFold export service and inspect intermediate and final PDFs. They do not change product defaults or certify accessibility. All inputs are deterministic synthetic documents generated by `corpus.py`: prose, mixed semantics, long contents, tiled diagram and wide CSV.

From the repository root, with the locked dev and server extras installed and the matching Playwright Chromium available:

```sh
uv sync --frozen --extra dev --extra server
.venv/bin/python tools/a11y/qualify.py --output /absolute/new/evidence-directory
.venv/bin/python tools/a11y/compare.py /absolute/new/evidence-directory
```

The output directory must be new; existing evidence is never silently overwritten by the main run. Run on Linux where process-tree RSS is available and Chromium can use its normal sandbox. Do not disable the Chromium sandbox to make a probe pass. The bundled-browser discovery path is recorded; it may point to the development Playwright cache, not a shipped package.

Three alternating off/on trials per case run in fresh child processes, browsers and diagram caches. The sole export difference is a process-local override of `Page.printToPDF.generateTaggedPDF`. Timers cover the real service including startup, layout, print, heading mapping, bookmarks and final atomic publication. A 10ms sampler sums Python and descendant RSS; it can miss short peaks and double-count shared pages. It is not PSS, container memory, or a capacity guarantee. OS caches are warm, trial count is small, and differences within run variation are not established performance effects. Inspect `metrics.json` ranges and phases before reporting ratios.

Separate capture trials copy every print pass and its HTML, then inspect the final PDF. No-bookmarks captures use the existing settings option to isolate rewriting. `compare.py` produces a diagnostic document clone with an added bookmark/metadata, compares normalized structure nodes, checks language and parent-tree presence, and raster-compares every page at 72 dpi. PDF text extraction is recorded separately; it does not prove assistive reading order. The inspector is for these bounded, trusted synthetic PDFs, not hostile-file validation or complete PDF/UA validation.

To test the preservation hypothesis through the full service, `--worker --tagged --clone-bookmarks --source ... --settings '{}' --output ...` replaces the writer's append operation with document cloning only inside that child process. `--capture` retains its intermediate PDFs. Repeat this diagnostic separately and label its costs as hypothesis measurements; it is a historical diagnostic switch. Production bookmark rewriting now clones the document; the switch adds no different writer path. Table and diagram semantics still require native reading checks after any repair.

Retain `environment.json`, the generated corpus, per-trial metrics/reports, every final PDF, capture PDFs/HTML/inspection JSON, `summary.json`, `comparison.json` and checksums. Native screen-reader acceptance is a separate attended procedure against the exact packaged artifacts; these tools do not replace it.
